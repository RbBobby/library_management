# Обзор лекции: ООП на Python на примере библиотеки

Обезличенный конспект учебной сессии по основам объектно-ориентированного программирования.  
Практический пример — проект **Library Management** (`Book`, `Library`, `main.py`).

---

## Цель занятия

Понять базовые идеи ООП на простом примере:

- что такое **класс** и **объект**;
- зачем нужен **конструктор** `__init__`;
- что означает **`self`**;
- чем **метод** отличается от обычной **функции**;
- как разнести классы по файлам и собрать сценарий в `main.py`;
- как запускать и **отлаживать** код в Cursor.

---

## Краткое резюме

На занятии разобрали ООП через модель «книга + библиотека».

Класс — это шаблон (чертёж). Объект — конкретный экземпляр, созданный по этому шаблону.  
Для книги задали поля: название, автор, доступность. Для библиотеки — список книг и действия: добавить, показать, выдать, вернуть.

Отдельно проговорили:

- объекты живут в **оперативной памяти** во время работы программы;
- библиотека **хранит ссылки** на объекты книг, а не «переносит файлы»;
- методы вызываются у конкретного объекта: `library.add_book(...)`;
- в отладчике удобно смотреть `self`, список `books` и флаг `is_available`.

Аналогия с занятия: классы похожи на **строительные блоки** — сначала понимаешь форму блока, потом собираешь из них систему.

## Определения

### ООП (объектно-ориентированное программирование)

Подход к написанию программ, где код организуют вокруг **объектов**: у каждого объекта есть данные (состояние) и действия (поведение).

В этом проекте объекты — книги и библиотеки.

### Класс

**Класс** — описание / шаблон сущности: какие у неё данные и какие действия она умеет.

Пример: класс `Book` говорит: «у книги есть название, автор и статус; книгу можно красиво напечатать».

Класс сам по себе ещё не книга — это чертёж.

### Объект (экземпляр)

**Объект** — конкретная «вещь», созданная по классу.

```python
book_1984 = Book("1984", "George Orwell")
```

Здесь:
- `Book` — класс;
- `book_1984` — переменная, которая ссылается на объект;
- сам объект лежит в памяти программы.

Синоним: **экземпляр класса** (instance).

Можно создать много объектов одного класса — у каждого свои значения полей.

### Атрибут (поле, свойство)

**Атрибут** — данные, которые хранятся у объекта.

У `Book`:
- `title` — название;
- `author` — автор;
- `is_available` — доступна ли книга.

Обращение: `book.title`, `book.is_available`.

### Метод

**Метод** — функция, объявленная внутри класса. Работает с конкретным объектом.

Примеры:
- `library.add_book(book)` — метод библиотеки;
- `library.borrow_book("1984")` — метод выдачи.

Метод почти всегда получает `self` — текущий объект.

### Функция

**Функция** — обычный блок кода с именем, объявленный **вне** класса.

Пример в проекте: `main()`.

Отличие:

| | Функция | Метод |
|---|---|---|
| Где объявлена | вне класса | внутри класса |
| Вызов | `main()` | `library.display_books()` |
| Есть ли `self` | обычно нет | да (у методов экземпляра) |

### Инициализация

**Инициализация** — задание объекту начальных значений в момент создания.

Когда пишем `Book("1984", "George Orwell")`, происходит инициализация:
- создаётся новый объект;
- в него записываются title, author;
- `is_available` ставится в `True`.

Пока объект не инициализирован «правильно», у него может не быть нужных данных для работы.

### Конструктор / `__init__`

В Python начальную настройку объекта делает специальный метод **`__init__`**.

Его часто называют **конструктором** (строго говоря, конструктор — весь процесс создания объекта, а `__init__` — этап инициализации).

```python
def __init__(self, title, author):
    self.title = title
    self.author = author
    self.is_available = True
```

`__init__` вызывается автоматически при создании объекта.

### `self`

**`self`** — ссылка на **текущий** объект, с которым сейчас работает метод.

Внутри метода:
- `self.title` — название **этой** книги;
- `title` без `self` — просто параметр/локальная переменная.

При вызове `book` передаётся в метод как `self` автоматически:

```python
library.add_book(book)
# примерно как: Library.add_book(library, book)
```

Имя `self` — соглашение. Главное: первый параметр метода экземпляра всегда получает сам объект.

### Параметр и аргумент

- **Параметр** — имя в определении метода/функции (`title`, `author`, `book`).
- **Аргумент** — конкретное значение при вызове (`"1984"`, объект книги).

```python
def add_book(self, book):      # book — параметр
    ...

library.add_book(book_1984)    # book_1984 — аргумент
```

### Переменная и ссылка

**Переменная** хранит не сам объект «внутри имени», а **ссылку** на объект в памяти.

```python
book_a = Book("1984", "George Orwell")
book_b = book_a
```

`book_a` и `book_b` могут указывать на **один и тот же** объект.

Если потом написать:

```python
book_a = Book("1984", "Someone Else")
```

переменная `book_a` начинает ссылаться на **новый** объект; старый объект сам по себе никуда «не переезжает».

### Сигнатура метода

**Сигнатура** — «паспорт» метода: имя + список параметров.

Пример сигнатуры:

```text
borrow_book(self, title)
```

По сигнатуре понятно, как метод вызывать и что ему нужно передать.

### Абстракция

**Абстракция** — выделение главного и скрытие лишних деталей. В коде это «что умеет сущность», без привязки к конкретной реализации.

В проекте класс `Library` — **абстрактный** (`ABC`):

- описывает контракт: `display_books`, `borrow_book`, `return_book`;
- создать `Library()` напрямую **нельзя** — нужен конкретный тип;
- общая логика вынесена в `_borrow_physical_book`, `_return_physical_book`;
- `PublicLibrary`, `SchoolLibrary`, `DigitalLibrary` реализуют абстрактные методы по-своему.

Функция `demo_library(library: Library, ...)` в `main.py` работает с **любой** библиотекой через общий интерфейс — это и есть абстракция в действии.

### Инкапсуляция

**Инкапсуляция** — сокрытие внутреннего состояния объекта и доступ к нему через понятный интерфейс (свойства и методы).

В проекте:

- поля с `_` (`_title`, `_is_available`, `_books`) — «внутренние», для логики класса и отладки;
- `@property` (`title`, `is_available`, `books`) — безопасное чтение снаружи;
- изменение статуса книги — только через `borrow()` / `give_back()`, а не `book.is_available = ...`.

**Как дебажить:** в Variables смотрите `_books`, `_is_available`; в коде снаружи используйте свойства и методы.

### Волшебные (dunder) методы

**Волшебные методы** — специальные методы с двумя подчёркиваниями с двух сторон (`__init__`, `__str__` и др.).

Они подключаются к встроенному поведению Python:

- `__init__` — при создании объекта;
- `__str__` — при `print(object)` и `str(object)`.

### Список (list) как хранилище

В `Library` книги хранятся в **списке** `self.books`.

Список — упорядоченная коллекция элементов.  
Библиотека не «содержит файлы книг», а держит ссылки на объекты `Book` в памяти.

## Основные темы

### 1. Класс, объект, метод, функция

Сводка из определений выше:

| Понятие | Простыми словами | Пример в проекте |
|---|---|---|
| Класс | Шаблон / описание сущности | `Book`, `Library` |
| Объект (экземпляр) | Конкретная «вещь» по шаблону | `Book("1984", "George Orwell")` |
| Метод | Функция внутри класса, работает с объектом | `add_book`, `borrow_book` |
| Функция | Обычный код вне класса | `main()` |
| Инициализация | Заполнение объекта начальными данными | `__init__` у `Book` / `Library` |
| `self` | Ссылка на текущий объект | `self.title`, `self.books` |

Важно: объект **не перемещается** в класс. Класс описывает правила, а объект создаётся в коде (обычно в `main.py`) и потом передаётся в библиотеку.

### 2. Конструктор `__init__` и параметр `self`

При создании объекта:

```python
book = Book("1984", "George Orwell")
```

Python вызывает `__init__` и первым аргументом передаёт сам объект — это и есть `self`.

`self.title = title` означает:  
«у **этого** объекта сохрани название».

`self` — это ссылка на текущий экземпляр. Вручную его при вызове не передают:

```python
book.info()   # self подставится автоматически
```

### 3. Несколько файлов = несколько ролей

Типичная структура учебного проекта:

- `book.py` — класс книги;
- `library.py` — класс библиотеки;
- `main.py` — сценарий: создаём объекты и вызываем методы.

Так проще читать код: один класс — одна ответственность.

### 4. Библиотека как контейнер

`Library` хранит книги в списке (`self.books`) и умеет:

- добавить книгу;
- показать все книги;
- выдать / вернуть по названию;
- найти книгу.

Можно создать **две разные библиотеки** — у каждой свой набор книг и своё состояние в памяти.

### 5. Цикл и поиск книги

Методы вроде `borrow_book` обычно:

1. проходят по списку книг (`for`);
2. сравнивают название (`if`);
3. меняют статус доступности;
4. печатают результат.

На каждой итерации цикла переменная `book` указывает на **очередной** объект из списка.

### 6. «Волшебные» методы

Кратко затронули special methods. Пример в проекте — `__str__`:

```python
print(book)  # вызывается Book.__str__
```

Так настраивается, как объект выглядит при печати.

### 7. Отладка

На занятии показали запуск программы и работу с debugger:

- breakpoint на создании библиотеки / `add_book` / `borrow_book`;
- Step Into (`F11`) — зайти внутрь метода;
- Step Over (`F10`) — выполнить строку и идти дальше;
- панель **Variables** — смотреть `self`, `books`, `is_available`.

Подробная инструкция есть в `README.md`.

## Что важно запомнить

1. Класс = шаблон, объект = конкретный экземпляр.  
2. `__init__` задаёт начальное состояние объекта.  
3. `self` — «этот объект».  
4. Методы меняют или читают состояние объекта.  
5. Данные программы во время работы хранятся в RAM.  
6. Отладчик помогает увидеть, что реально происходит, а не только читать код глазами.
